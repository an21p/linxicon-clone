# Server-Side Embeddings API + Single-Origin Serving — Design

**Date:** 2026-06-21
**Status:** Approved (pending spec review)

## Problem

The MiniLM backend loads `@huggingface/transformers` (≈23 MB onnx/wasm + model weights) into the browser from the HF CDN on first use. This makes the initial load slow. The Numberbatch backend also ships a 9.9 MB int8 matrix to the browser. We want to move embedding work off the client behind an HTTP API, and serve everything through a single origin so the existing cloudflared tunnel can expose it for remote testing.

## Goal

Replace the in-browser embedding workers with a server-side **embeddings API**, served by a single Node service that (in production) also serves the built static site. The browser downloads no model and no vector matrix; it fetches vectors per word over HTTP. The game's engine, math, model picker, and model-namespaced cache are preserved.

## Decisions (locked)

- **Stack:** single Node service (Fastify), reusing `@huggingface/transformers` so precomputed and live MiniLM vectors are produced by the same implementation (vector parity).
- **Vector sourcing:** hybrid — precomputed in-memory lookup tables for both models (fast path) + live MiniLM inference fallback for non-curated words.
- **(a) MiniLM table:** committed precomputed asset (`public/minilm.bin` + index), generated by an offline script, so server boot and first remote test are instant.
- **(b) Numberbatch:** curated-lookup-only for v1 (no full-516k fallback). The game only ever requests curated words.

## Architecture

### Single Node service (`server/`)

A Fastify service is the single origin behind the tunnel:

- Serves `POST /api/embed` and `GET /api/health`.
- In **production**, also serves the built `dist/` static site via `@fastify/static`, so the tunnel points at one port.
- Loads the two precomputed lookup tables into memory at boot.
- Lazily loads the MiniLM model (via `@huggingface/transformers`) only when a live fallback is first needed.

Default port: `8787` (override via `PORT`).

### Reverse-proxy / serving topology

- **Dev (live edit):** run Vite + the Node service. Vite config adds `server.proxy = { '/api': 'http://localhost:8787' }`. Cloudflared tunnels the Vite dev server (allowedHosts already permissive); `/api/*` proxies to Node. Single hostname.
- **Prod / remote demo:** `vite build` → `dist/`; `node server` serves `dist/` + `/api`. Cloudflared tunnels Node. Single origin, single process.

npm scripts:
- `dev:api` — run the Node service (watch).
- `dev` — Vite (unchanged) with the `/api` proxy.
- `serve` — `vite build` then start Node serving `dist/` + API (the remote-testing entrypoint).
- `build:vectors:minilm` — offline MiniLM table generation (run once when the curated vocab changes).

## API Surface

### `POST /api/embed`

Request:
```json
{ "model": "minilm" | "numberbatch", "words": ["cow", "milk"] }
```

Response:
```json
{ "model": "minilm", "dim": 384, "vectors": [[/* 384 normalized floats */], [/* ... */]] }
```

- Vectors are L2-normalized `float32` arrays serialized as JSON number arrays.
- Order of `vectors` matches the order of `words`.
- A word with no available vector yields `null` in that slot.
- Batch-friendly: `newGame` sends 2 words, `reEmbedCurrent` sends N, `submitWord` sends 1.
- Validation: `model` must be a known id; `words` a non-empty array of strings (cap length, e.g. ≤ 256, to bound work). Invalid → HTTP 400.

### `GET /api/health`

```json
{ "ok": true, "models": ["minilm", "numberbatch"] }
```

Used by the client to flip `ready` (near-instant; no model download).

## Server Vector Sources (hybrid)

A shared `VectorTable` abstraction (in `server/`) wraps an int8 matrix + `Map<word,row>` + `dim`, with `lookup(word): Float32Array | null` (dequantize ÷127 then L2-normalize — identical math to the existing `src/lib/numberbatch.ts`).

- **Numberbatch:** load `public/numberbatch.bin` + `public/numberbatch-index.json` at boot. `lookup` only; miss → `null`.
- **MiniLM:**
  - Fast path: load `public/minilm.bin` + `public/minilm-index.json` at boot; `lookup`.
  - Fallback: on miss, run live inference via `@huggingface/transformers` (`pipeline('feature-extraction', 'Xenova/all-MiniLM-L6-v2')`, `{ pooling: 'mean', normalize: true }`), memo-cache the result in an in-memory `Map`. Model is loaded once, lazily.

### MiniLM table generation (offline, committed)

`scripts/build-minilm.mjs` (Node, run with the repo's Node + `@huggingface/transformers`):
- Read the curated word list from `src/lib/words/dictionary.json` (33,114 words).
- Embed each word with `Xenova/all-MiniLM-L6-v2` (`mean`+`normalize`), L2-normalize (defensive), quantize `clip(round(v*127), -127, 127)` to int8.
- Emit `public/minilm.bin` (int8 row-major N×384) + `public/minilm-index.json` (`{ dim: 384, words: [...] }`, same word order as `dictionary.json`).
- Print vocab size and asset bytes.
- Reuse `QUANT_SCALE = 127` and the row-major layout that match Numberbatch and the server/client dequantize.

The curated word order in `minilm-index.json` and `numberbatch-index.json` is identical (both equal `dictionary.json`), so a single shared word list governs both tables.

## Client Changes

### HTTP embedder replaces the workers

`src/lib/embeddings.ts` is reworked: `createEmbeddings(modelId)` returns an `EmbeddingsHandle` whose `embedder` POSTs to `/api/embed`.

- `Embedder` interface (`embed(word) → Promise<Float32Array>`) unchanged.
- `withCache` and the model-namespaced cache key `vec:${modelId}:${word}` unchanged (still prevents 384/300-dim collisions in idb/in-mem).
- `embedFn(word)` → `POST /api/embed { model: modelId, words: [word] }` → `Float32Array` from `vectors[0]`; a `null` vector rejects (mirrors the old worker `error` path; the game surfaces it as "something went wrong").
- `onReady` fires after a `GET /api/health` succeeds; `onProgress` reports 0→100 across that single request (effectively instant). `onError` fires on health/network failure.
- `destroy()` aborts any in-flight requests (AbortController); no worker to terminate.
- API base resolves to `'/api'` (same origin → works through the proxy/tunnel).

### Removed from the client

- `src/lib/embeddings.worker.ts`, `src/lib/numberbatch.worker.ts` (logic moves server-side).
- Client-side Numberbatch asset fetch and worker selection.
- The `worker: { format: 'es' }` Vite config (no client workers remain).
- `src/lib/numberbatch.ts` pure helpers move to the server (shared dequantize/lookup). The client no longer needs them.

### Unchanged

- `src/lib/models.ts` registry, `src/lib/game.ts` (`setEmbedder`/`reEmbedCurrent`), `src/lib/engine/*`, `src/lib/math.ts`, `Hud.svelte` picker, `App.svelte` switch orchestration (it already tears down/recreates the embeddings handle and re-embeds; with HTTP this is just faster). `App.svelte`'s loading screen stays but completes near-instantly.

## Data Flow

1. Browser loads → `createEmbeddings('numberbatch')` → `GET /api/health` → `ready`.
2. `newGame` → `POST /api/embed { model, words:[a,b] }` → engine seeded.
3. `submitWord(w)` → `POST /api/embed { model, words:[w] }` → `engine.addWord`.
4. Switch model in the picker → new HTTP embedder for the new `modelId` → `reEmbedCurrent` → `POST /api/embed { model:new, words:[all graph words] }` (one batched request) → engine rebuilt; edges/gap recompute. No cross-model mixing (cache namespaced by model).
5. Server `lookup` hit → dequantized vector; MiniLM miss → live inference (once-loaded model), memo-cached.

## Testing

**Server** (`server/` tests, run under the same vitest or a node test runner):
- `VectorTable.lookup` returns a correct-dim, unit-norm `Float32Array` for a known row; `null` for an unknown word (tiny synthetic table).
- `POST /api/embed` (via Fastify `inject`): batch order preserved; correct `dim` per model; unknown Numberbatch word → `null`; MiniLM miss invokes a **mocked** inference path (no real model in tests) and returns a 384-dim vector; bad `model`/empty `words` → 400.
- `GET /api/health` → `{ ok:true, models:[...] }`.

**Client:**
- HTTP embedder returns a normalized `Float32Array` for a word (mock `fetch`); `vectors[0] === null` → rejects.
- Cache namespacing preserved (`cacheKey('minilm','cow') !== cacheKey('numberbatch','cow')`) — keep the existing test.
- Model switch re-requests under the new model id (mock `fetch`, assert request body `model`).
- Engine/game/puzzles/dictionary/math tests unchanged.

## Constraints

- Runtime network from the browser is now only same-origin `/api/*` (plus the static site). The HF CDN fetch moves server-side and happens at most once (live fallback).
- Don't change engine/math/graph logic or the model picker UX beyond the embedder transport swap.
- Keep `QUANT_SCALE = 127`, the int8 row-major layout, `DEFAULT_MODEL`, and the curated word order as the single source of truth shared by both tables.
- `@huggingface/transformers` stays a dependency (now server-side).

## Out of Scope (v1)

- Full-516k Numberbatch fallback.
- Authentication / rate limiting on the API (local + tunnel testing only).
- Persisting the MiniLM live-inference memo cache to disk (in-memory per process is enough).
